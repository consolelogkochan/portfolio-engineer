# 公開の後の運用の一覧

## この文書について

**意義**：公開の後に、人が定期的に、または何かが起きたときに行う運用を、一目で見て、漏れが無いかを点検するための一覧（7-9f で作った。2026-11-03）。

**正の記録は、手順書（[`docs/server-setup.md`](server-setup.md)）と台帳（[`docs/ledger.md`](ledger.md)）にある。** この文書はその索引で、写しである。

- 正を変えたら、この文書も同じコミットで直す（[`docs/development.md`](development.md) の4節）
- コマンドと細かい手順は書かない。各行の「正の場所」を見る
- 今の状態の一覧なので、経緯は書かない

**月次の点検は人が行う。飛ばしても、どこにも記録は残らない**（手順書37節の「受け入れた穴」）。予定は、作業者のカレンダーの繰り返しに頼っている（40節）。

## 1. 定期の点検

## 3. 起きたときに行うこと

| きっかけ | 行うこと | 気づく経路 | 正の場所 |
| --- | --- | --- | --- |
| OS のパッケージの Critical の告知 | 修正版を手で入れ、サービスを再起動し、起動時刻を見る | 人が報道などで気づく（仕組みは無い） | 9節、台帳 41-7 |
| 証明書の警告が出た | 証明書の一覧と、サーバーが出している証明書を見て直す | ログインのときの表示 | 37節 |
| 更新の出力に、先送りされた再起動が出た | 台帳 41-7 に記録し、次に再起動する機会を意識する | 月次の更新の出力 | 40節 |
| 更新に grub が含まれる | 自分が見ている時間帯に再起動し、起動することを見る | 月次の更新の前の確かめ | 40節 |
| PHP の CVE-2026-115560 の修正版が出た | 9節の手順で入れる | 月次の更新に合わせた確かめ | 台帳 41-6 |
| 500 が出て、原因が送信の失敗だった | 送信の失敗の未検証の形を調べる | ログ | 台帳 41-7 |
| デプロイ用の秘密鍵を失った、または漏れた疑いがある | 漏れた場合は先に古い鍵の行を消し、鍵を作り直して差し替える | `Deploy` の失敗、または人が気づく | 30節 |

## 6. 受け入れた穴

| 穴 | 正の場所 |
| --- | --- |
| 月次の点検は人が行い、飛ばしたことは残らない | 37節 |
| サイトの停止や転送の失敗に気づくまで、最大16日かかる（外の監視は使わない） | 37節、40節 |
| 証明書の更新の失敗を知らせる通知は作らない | 37節 |
| OS の Critical の告知に気づく仕組みは無い | 9節、台帳 41-7 |
| 依存の欠陥に気づくのは、月次の点検の監査だけ。最大で16日遅れる | 40節の依存の更新の方針 |
| バックアップは未設定 | 40節 |
| 連絡の経路は問い合わせのフォーム1つ | 19節 |
| 通信が切れると、もう一度送ったときに同じメールが2通届きうる | 19節、`docs/development.md` の11節 |
| HSTS を入れたので、証明書が切れると、一度訪れた人は警告を越えて進めない | 39節 |
| 公開中のデプロイの途中の数秒に、ルートや画面の部品を足したコミットでは、404 や描けない画面が出うる（推測） | 30節 |
| 迷惑な送信に Resend の1日の枠（100通）を使い切られると、その日の問い合わせが送れない | 37節 |
