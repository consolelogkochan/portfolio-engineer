このファイルは、このプロジェクトの持ち越し（回収先のカードがあるもの・無いもの）を記録する唯一の台帳である。サーバーの設定に限らず、アプリケーション・開発環境・記録の進め方の項目も含む。

小節の番号「41-n」は、手順書（`docs/server-setup.md`）の41節からこのファイルへ移した経緯による（2026-10-18 に移した）。既存の参照を壊さないため、番号はそのまま使う。本文の「n節」は、手順書の節を指す。

申し送りの本文は、このファイルにだけ書く。統一ログには、この台帳の小節と行への参照だけを書く。

持ち越しの正はこの台帳である。Issue は、着手するカードが決まった作業にだけ使い、台帳の行に Issue 番号を書く。「〜のときに対応する」という条件待ちのものは、Issue にせず、この台帳にだけ置く。

手順書は、サーバーの設定と、その判断の根拠を書く場所である。

**「401 はユーザー名を明かさず」の根拠**

出典：401 応答（チャレンジ）に含まれるのは認証スキームと realm（必須）、および任意の charset のみで、ユーザー名は含まれない（RFC 7617 §2。https://datatracker.ietf.org/doc/html/rfc7617 ）。

実測（2026-09-02）：存在するユーザー名と存在しないユーザー名で、401 の応答は完全に一致した（ステータス、`www-authenticate`、`content-length` = 172、本文）。

```bash
curl -si -u '<USER>:wrong-password' https://new.ikshowcase.site/
curl -si -u 'nosuchuser:wrong-password' https://new.ikshowcase.site/
```

未検証：応答時間による区別は確かめていない。サーバー上で 5 回ずつ測定したところ、中央値は存在する側 0.0176 秒、存在しない側 0.0147 秒で、差は約 2.9 ミリ秒。方向と大きさは SHA-512 crypt の計算時間として説明できるが（推測）、範囲が完全に重なっており（0.0157–0.0360 対 0.0144–0.0285）、TLS ハンドシェイクのばらつきと分離できていない。この結果は判断（7-9 の認証撤去で解消する）を変えないため、これ以上は測らない（6-4）。

### 41-8. 判断は済んでいるが、理由の記録が無いもの

**`open_basedir`：検討したうえで見送った。見送った理由が記録されていない。**

7-3c より前の判断であり、この文書にも統一ログにも理由が残っていない。**理由の記録が無いという事実そのものを、ここに記録しておく。**

**`.npmrc` の `ignore-scripts=true`：初期セットアップから入っている。入れた理由の記録がない。**

`.npmrc`（Git 管理下）に `ignore-scripts=true` があり、依存パッケージのインストール時スクリプト（`preinstall` / `install` / `postinstall`）が実行されない状態になっている。3-2 の初期セットアップのコミットに、単独ではなく一括で含まれて入った。この文書にも統一ログにも入れた理由が残っておらず、開発者本人にも設定した記憶がない。**理由の記録が無いという事実そのものを、ここに記録しておく。**

npm はカレントディレクトリからプロジェクトの `.npmrc` を探して適用する。`-g`（グローバルインストール）でも同じで、リポジトリの中から実行した `npm install -g` にも効く。このため、開発機での作業と CI の `npm ci`（`ci.yml`）の2か所に適用されている。実際、リポジトリ内から実行した `npm install -g` が postinstall を実行できず、開発機で Claude Code が起動しなくなる形で表面化した（7-4d の作業中）。7-4e より前は本番サーバーの `bin/deploy.sh` の `npm ci` にも効いていたが、7-4e でビルドが CI へ移り、サーバーでは `npm` を実行しなくなった（21節・30節）。

- 効果：依存パッケージのインストール時スクリプトが実行されない。悪意あるパッケージが最もよく使う経路が塞がれる。ただし `npm run build` の中で動くコード（ビルドツールのプラグインや設定ファイル）は通常のモジュール読み込みなので止まらない。
- 代償：postinstall を必要とするパッケージを静かに壊す。エラーが分かりにくい形で出る。上記の Claude Code のインストール障害がその実例。

判断すべきこと：意図して維持するのか、外すのか。維持するなら理由を記録する。21節（`npm audit` のゲート）はこの設定を根拠として書き足せる位置にあるが、理由が定まるまでは書き足さない（根拠にした設定が後で消えると、根拠が黙って崩れるため）。

（`.npmrc` にはもう1行 `audit=true` がある。npm の既定と同じ挙動を明示しているだけの別設定で、認証情報は含まれていない。）
